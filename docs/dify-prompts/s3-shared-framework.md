# S3 渠道结构诊断报告生成框架（五屏版）

## 1. 文档目标

一期仅生成 S3 渠道结构诊断报告，不生成 S1、S2、S4 报告内容。

本框架将 S3 报告拆分为五个屏幕：

1. 渠道全景
2. 品类营收结构
3. 获客成本信号
4. 投放有效性
5. 总结

原六屏框架中的「品类 × 渠道依赖度」「内部渠道」「转介绍」三屏，因当前指标层缺少 `acquisition_source_type`、品类×渠道交叉聚合、`customer_id`、`referral_*` 等支撑字段，一期不生成，也不作为占位屏输出"数据缺口"——直接从屏号序列中移除。待相应字段接入后再补齐为独立屏。

本框架只定义报告生成方式，不预先编写实际诊断结论。核心要求如下：

- 每个结论必须可追溯到指标数据或规则结果。
- LLM 不得创造业务原因。
- 所有解释性推理必须明确标注"推断"。
- 指标由指标层计算，规则由 Rule Engine 判断，LLM 只负责受约束的语言组织。

---

## 2. 总体生成原则

### 2.1 结论类型

系统只允许输出三类结论。

| 结论类型 | 含义 | 固定前缀 | 必须携带的信息 |
| --- | --- | --- | --- |
| 数据事实 | 指标层直接计算所得 | `【数据事实】` | 指标、数值、单位、期间、维度、数据引用 |
| 规则结论 | Rule Engine 已执行并返回 | `【规则结论】` | `rule_id`、命中状态、阈值、指标快照、证据 |
| 受限推断 | 基于多个事实进行的解释性归纳 | `【推断】` | 支撑事实、推断边界、置信度、待验证项 |

不属于以上三类，或不能提供证据引用的内容，不进入最终报告。

### 2.2 统一证据引用协议

每条结论必须绑定 `evidence_refs`。

```json
{
  "conclusion_id": "S3-P1-C01",
  "conclusion_type": "data_fact | rule_result | inference",
  "statement": "结论文本",
  "evidence_refs": [
    {
      "source_type": "metric | rule",
      "source_id": "channel_month_metrics",
      "metric": "cost_share",
      "dimension": {
        "channel_group": "PAID_EXTERNAL"
      },
      "period": {
        "start": "YYYY-MM",
        "end": "YYYY-MM"
      },
      "value": 0.0,
      "unit": "RATIO"
    }
  ],
  "inference_label": null,
  "confidence": "high | medium",
  "unverified_items": []
}
```

约束：

- `data_fact` 和 `rule_result` 不得包含模型生成的业务原因。
- `inference` 的正文必须以"推断："开头。
- 推断只能描述现象之间可能存在的关系，不能断言因果。
- 没有证据引用的结论在渲染前直接拦截。
- 原始值、比例、环比、同比均由指标层计算，LLM 不自行运算。

### 2.3 通用数据质量字段

每一屏都应包含以下数据质量信息：

```text
data_period_start
data_period_end
complete_months
incomplete_months
missing_fields
unsupported_metrics
unsupported_rules
```

不完整月份可以展示，但不得参与跨月趋势规则。

## 3. 第一屏：渠道全景

### 3.1 分析目标

回答：当前获客规模、成本和效率在观察期内如何变化。

本屏使用 `month + channel` 聚合指标，不依赖渠道类型映射表；如无该映射表，不生成外部付费/内部流转/转介绍的结构分解，只展示按三级渠道的规模与效率趋势。

### 3.2 需要输入的数据字段

```text
month
channel
cost
leads
first_order_orders
first_order_revenue
first_order_net_revenue
cac
cac_rate
channel_roi
```

### 3.3 可使用的规则结果

- R61：无效投放。

### 3.4 输出格式

按 [screen-01（共用上下文自带）] 的模板执行。

---

## 4. 第二屏：品类营收结构

### 4.1 分析目标

回答：品类营收的下行是个别现象还是整体趋势，品类之间是否出现分化。

### 4.2 需要输入的数据字段

```text
month
category
category_revenue
revenue_share
```

### 4.3 可使用的规则结果

- R3：营收集中度。
- R4：营收过于分散。
- R5：核心品类下行趋势。
- R8：涨跌两极分化。
- R9：系统性下跌。

### 4.4 禁止事项

- 不根据品类名称判断"获客型""深耕型"等经营类型。
- 不把首单营收等同于整体收入或利润。
- 极端增速需说明是否来自极小基数，不当作重要变化直接引用。

---

## 5. 第三屏：获客成本信号

### 5.1 分析目标

回答：哪些渠道的获客成本出现持续性上行，风险覆盖范围有多大。

### 5.2 需要输入的数据字段

```text
month
channel
cac_rate
```

### 5.3 可使用的规则结果

- R36：CAC 连续上升。
- R37：CAC 环比跳升。

### 5.4 禁止事项

- 不得将本屏标题写成"客户结构"；R36/R37 的事实语义是渠道 CAC，不是客户结构。
- 不推断成本上行的原因（平台竞价、素材衰退、预算不足等）。
- 不给出停投、加投或预算调整结论。

---

## 6. 第四屏：投放有效性

### 6.1 分析目标

回答：无效投放（ROI<0.5 渠道消耗占比）风险当前是否触发，覆盖范围是什么。

### 6.2 需要输入的数据字段

```text
month
ineffective_cost
total_cost
ineffective_cost_share
```

### 6.3 可使用的规则结果

- R61：无效投放(P0)。

### 6.4 禁止事项

- 未命中不得写成"投放整体健康"或"渠道结构没有问题"。
- 必须说明本屏结论只覆盖低效消耗占比这一项，不代表渠道集中度、流量来源结构等未检查项。

---

## 7. 第五屏：总结

### 7.1 分析目标

将前四屏已经生成并通过证据校验的内容压缩为：核心结论、已确认风险、优先核查顺序、数据缺口。

第五屏不能产生前四屏从未出现的新结论。

### 7.2 需要输入的数据字段

总结屏不重新读取明细数据，只消费前四屏的结构化输出：

```text
screen_id
conclusion_id
conclusion_type
statement
evidence_refs
rule_id
confidence
unverified_items
data_gaps
```

### 7.3 禁止事项

- 不生成新的业务原因。
- 不生成未经数据支持的战略动作。
- 不把"可能"改写成确定性结论。
- 不把规则未命中写成"没有风险"。
- 不输出"优化投放、加强品牌、调整 KPI"等泛化建议。

---

## 8. 报告生成链路

```text
渠道明细数据
  → 字段标准化
  → 月 × 渠道 / 月 × 品类 聚合
  → 指标计算
  → S3 Rule Engine（R3/R4/R5/R8/R9/R36/R37/R61）
  → 证据对象
  → 五屏内容生成器
  → 结论追溯校验
  → 屏幕输出
```

---

## 9. 一期能力边界

### 9.1 当前可以直接使用

- 月 × 三级渠道的成本、线索、首单订单、首单收入、CAC、CAC率、渠道ROI。
- 月 × 品类的首单营收与占比。
- 现行可执行的 R3、R4、R5、R8、R9、R36、R37、R61。

### 9.2 一期不生成（待字段补齐后恢复为独立屏）

- 渠道类型版本化映射（`acquisition_source_type`）。
- 月 × 品类 × 渠道交叉聚合表。
- 内部流转的源品类—目标品类路径、去重客户数、流转率。
- 转介绍人数、推荐关系、转介绍转化率。

以上字段缺失期间，不生成对应屏幕，也不在已有屏幕中臆测其内容。
